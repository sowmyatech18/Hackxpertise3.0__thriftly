============================================================
1. APP CONCEPT
============================================================

THRIFTLY is a campus-exclusive circular marketplace where verified college students can:

💰 SELL
🔄 EXCHANGE
🎁 GIVE AWAY
🕒 RENT

pre-owned items to other students within their verified campus community.

The app helps students save money, reuse useful items, reduce unnecessary waste, and give unused belongings a second life.

THRIFTLY is NOT a traditional e-commerce application.

It is a campus circular marketplace focused on:

• Student-to-student reuse
• Campus verification
• Safe campus meetups
• Selling
• Exchanging
• Giving away
• Renting
• Negotiation
• Wishlists
• Campus exchange points
• Semester-end clearance
• Personal reuse impact

============================================================
2. VERY IMPORTANT DATA RULE
============================================================

ALL USER DATA MUST BE DYNAMIC AND USER-INPUT BASED.

DO NOT HARD-CODE REALISTIC PERSONAL INFORMATION.

DO NOT INVENT:

• Student names
• Seller names
• Buyer names
• Profile pictures
• College email addresses
• Student IDs
• Phone numbers
• Addresses
• Personal information
• Fake reviews
• Fake ratings
• Fake transaction histories
• Fake offers
• Fake chat conversations
• Fake user profiles
• Fake account information

The prototype should use input fields, placeholders, dynamic variables, empty states, and user-created data.

If a screen needs user information, display:

[Student Name]

[College Email]

[Student ID]

[Selected Campus]

or an appropriate empty state.

The application must never pretend that randomly generated people are real users.

============================================================
3. DYNAMIC MARKETPLACE DATA
============================================================

All marketplace listings must be created through the CREATE LISTING flow.

Do NOT hard-code fictional seller information.

Each listing should dynamically contain:

• Item photos uploaded by the user
• Item title entered by the user
• Category selected by the user
• Description entered by the user
• Condition selected by the user
• Transaction type selected by the user
• Price entered by the user
• Original new price entered by the user, if applicable
• Exchange preference entered by the user
• Rental price entered by the user
• Rental availability entered by the user
• Deposit entered by the user, if applicable
• Campus exchange point selected by the user
• Listing status generated by the application

Seller identity should come from the authenticated account.

Never invent seller identity.
